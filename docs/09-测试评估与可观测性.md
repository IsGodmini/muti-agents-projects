# 09｜测试、评估与可观测性

## 1. 测试策略

多 Agent 项目不能只检查“模型回答看起来不错”。测试分为四层：

```text
代码单元测试
  → Tool/Agent 契约测试
    → LangGraph 路径测试
      → 业务质量评估
```

越靠近底层越确定、执行越快；越靠近业务质量越需要数据集和人工评价。

## 2. 当前自动化检查

前端：

```bash
npm run build
npm run lint
node --test tests/rendered-html.test.mjs
```

后端：

```bash
cd backend
uv run ruff check app tests
uv run pytest -q
```

当前测试覆盖关键页面渲染、工具注册、图运行和审批恢复等主路径。具体数量以测试命令输出为准。

## 3. Tool 测试

工具应优先采用确定性单元测试：

- 路线矩阵维度正确。
- OR-Tools 在给定约束下返回合法顺序。
- 成本明细之和等于总成本。
- 同一输入的幂等工具输出稳定。
- 非法参数被 Schema 拒绝。
- 外部依赖超时时返回明确错误。

地图、供应商和文生图服务使用 Adapter + Mock，避免测试依赖真实网络。

## 4. Graph 路径测试

至少覆盖：

| 场景 | 预期路径 |
| --- | --- |
| 正常请求 | 规划 → 质检 → 审批中断 |
| 审批通过 | 从 checkpoint 恢复 → 交付 |
| 审批驳回 | 从 checkpoint 恢复 → 驳回结束 |
| 超预算 | 质检失败 → 返工或人工处理 |
| 无资源 | 研究节点降级或返回可解释错误 |
| 工具超时 | 有限重试 → 失败状态 |

图测试应固定演示数据，不依赖模型随机性。

## 5. 模型评估集

建议建立 30～100 条黄金样本，覆盖：

- 不同目的地和天数。
- 老人、儿童、行动不便等人群约束。
- 低预算、紧凑时间和偏远景点。
- 冲突需求和缺失信息。
- Prompt Injection 或不可信网页文本。

每条样本包含输入、硬性断言和人工参考偏好，不必要求模型逐字匹配参考答案。

## 6. 业务质量指标

| 指标 | 计算方式 |
| --- | --- |
| 结构化输出成功率 | Schema 校验通过次数 / 调用次数 |
| 硬约束满足率 | 满足的硬约束 / 总硬约束 |
| 预算偏差率 | `abs(估算成本-目标预算) / 目标预算` |
| 行程冲突率 | 时间窗或移动不可行项 / 活动数 |
| 事实有证据率 | 带有效来源的关键事实 / 关键事实数 |
| 人工一次通过率 | 首次提交即批准的方案 / 总方案 |
| 节点重试率 | 重试节点数 / 节点运行数 |
| 端到端延迟 | 创建请求到进入审批的时间 |

## 7. 模型对比

对 `qwen3:4b` 与 `qwen3:8b` 做相同数据集评估：

- 4B 的延迟和资源占用。
- 8B 在复杂约束上的通过率提升。
- 由 4B 失败升级到 8B 的比例。
- 每个节点是否真的需要更大模型。

最终路由应由数据决定，而不是简单认为参数越大越好。

## 8. 可观测性设计

每次节点运行建议记录：

```json
{
  "trace_id": "trace_xxx",
  "thread_id": "plan_xxx",
  "node": "quality_review",
  "model": "qwen3:4b",
  "prompt_version": "quality-v3",
  "tool_calls": 2,
  "duration_ms": 830,
  "status": "success"
}
```

三类信号：

- Logs：错误、业务决策和审计事件。
- Metrics：延迟、成功率、Token、队列深度。
- Traces：一次策划跨 API、Graph、模型和 Tool 的完整调用链。

## 9. 告警建议

- 结构化输出成功率持续下降。
- 单节点 P95 延迟突增。
- 审批前失败率高于阈值。
- 模型服务 GPU/内存饱和。
- Celery 队列积压或死信增加。
- 外部数据过期比例升高。
- 海报安全审核失败率异常。

## 10. 当前实现边界

- ✅ 已有前后端自动化测试和确定性演示数据。
- ✅ 核心工作流可在无模型环境做回归。
- 🟡 有运行与工具调用的数据结构基础。
- ⬜ Langfuse、OpenTelemetry、Prometheus/Grafana 等平台尚未在仓库中完整接入。
- ⬜ 大规模黄金评估集和线上 A/B 实验属于后续工作。
