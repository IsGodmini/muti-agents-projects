# 09｜测试、评估与可观测性

## 1. 测试策略

多 Agent 项目不能只检查"模型回答看起来不错"。测试分为三层：

```text
代码单元测试（Tool 契约）
  → LangGraph 路径测试
    → 业务质量评估
```

越靠近底层越确定、执行越快；越靠近业务质量越需要数据集和人工评价。

## 2. 当前自动化检查

```bash
uv run ruff check app tests cli.py
uv run pytest -q
```

测试文件：

| 文件 | 覆盖内容 |
| --- | --- |
| `tests/test_tools.py` | 工具注册、OR-Tools 优化、成本计算、Tavily 结果解析、异步工具调用约束 |
| `tests/test_graph.py` | 完整工作流路径、审批中断与恢复、约束校验 |

`tests/conftest.py` 通过 autouse fixture 设置 `MOCK_MODEL_MODE=true`，并 Mock `ModelGateway.structured_completion` 与 `tool_registry.ainvoke`，因此测试不消耗真实 API 配额，也不依赖网络。

## 3. Tool 测试

工具采用确定性单元测试：

- 路线矩阵维度正确。
- OR-Tools 在给定约束下返回合法顺序。
- 成本明细之和等于总成本，售价不超过预算上限。
- 非法参数被 Schema 拒绝。
- 异步工具必须通过 `ainvoke` 调用，误用 `invoke` 立即报错。
- 未配置 Tavily API Key 时明确抛出异常。

MCP 搜索使用 Fake Service 验证，避免测试依赖真实网络。

## 4. Graph 路径测试

覆盖场景：

| 场景 | 预期路径 |
| --- | --- |
| 正常请求 | 解析 → 检索 → 编排 → 校验 → 报价 → 质检 → 审批中断 |
| 审批通过 | 从 checkpoint 恢复 → 海报 → 存档 |
| 审批驳回 | 从 checkpoint 恢复 → mark_rejected |

图测试固定 Mock 数据，不依赖模型随机性。

## 5. 模型评估集（规划）

建议建立 30～100 条黄金样本，覆盖：

- 不同目的地和天数。
- 老人、儿童、行动不便等人群约束。
- 低预算、紧凑时间和偏远景点。
- 冲突需求和缺失信息。
- Prompt Injection 或不可信网页文本。

每条样本包含输入、硬性断言和人工参考偏好，不必要求模型逐字匹配参考答案。

## 6. 业务质量指标

| 指标 | 计算方式 |
| --- | --- |
| 结构化输出成功率 | Schema 校验通过次数 / 调用次数 |
| 硬约束满足率 | 满足的硬约束 / 总硬约束 |
| 预算偏差率 | `abs(估算成本-目标预算) / 目标预算` |
| 行程冲突率 | 时间窗或移动不可行项 / 活动数 |
| 事实有证据率 | 带有效来源的关键事实 / 关键事实数 |
| 人工一次通过率 | 首次提交即批准的方案 / 总方案 |
| 端到端延迟 | 创建请求到进入审批的时间 |

## 7. 可观测性设计（规划）

每次节点运行建议记录：

```json
{
  "trace_id": "trace_xxx",
  "thread_id": "plan_xxx",
  "node": "quality_review",
  "model": "ark-code-latest",
  "prompt_version": "quality-v3",
  "tool_calls": 2,
  "duration_ms": 830,
  "status": "success"
}
```

三类信号：

- Logs：错误、业务决策和审计事件。
- Metrics：延迟、成功率、Token、队列深度。
- Traces：一次策划跨 CLI、Graph、模型和 Tool 的完整调用链。

## 8. 告警建议

- 结构化输出成功率持续下降。
- 单节点 P95 延迟突增。
- 审批前失败率高于阈值。
- Tavily 搜索失败率升高。
- 外部数据过期比例升高。
