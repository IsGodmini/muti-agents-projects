# 09｜测试、评估与可观测性

## 1. 测试策略

多 Agent 项目不能只检查"模型回答看起来不错"。测试分为三层：

```text
代码单元测试（Tool 契约）
  → LangGraph 路径测试
    → 业务质量评估
```

越靠近底层越确定、执行越快；越靠近业务质量越需要数据集和人工评价。

## 2. 当前自动化检查

```bash
uv run pytest -q -m "not integration"   # 17 个单元测试
uv run ruff check app tests cli.py      # 静态检查
# 完整运行（需 ComfyUI）：uv run pytest -q  # 17 单元 + 3 集成
```

测试文件：

| 文件 | 覆盖内容 | 数量 |
| --- | --- | --- |
| `tests/test_tools.py` | 工具注册与风险分级、成本计算、路线矩阵、Tavily 结果解析、异步工具调用约束 | 7 |
| `tests/test_graph.py` | 完整工作流路径、审批中断与恢复、驳回路径 | 2 |
| `tests/test_evaluation.py` | 质量评估框架：完美方案高分、时间冲突、每日超载、必去覆盖、避雷违反、溯源、估算占比 | 8 |
| `tests/test_comfyui.py` | ComfyUI 连通性、文生图端到端（`integration` 标记，默认跳过） | 3 |

`tests/conftest.py` 通过 autouse fixture 设置 `MOCK_MODEL_MODE=true`、`MOCK_IMAGEGEN=true`、`TAVILY_FALLBACK_TO_DEMO=true`，因此单元测试不消耗真实 API 配额，也不依赖网络。

## 3. Tool 测试

工具采用确定性单元测试：

- 工具注册数量与风险分级覆盖全部三级。
- 路线矩阵正确使用提供的交通时间。
- 成本明细之和等于总成本，售价不超过预算上限。
- 非法参数被 Schema 拒绝。
- 异步工具必须通过 `ainvoke` 调用，误用 `invoke` 立即报错。
- 未配置 Tavily API Key 时明确抛出 `MCPToolError`。

MCP 搜索使用 Fake Service 验证，避免测试依赖真实网络。

## 4. Graph 路径测试

覆盖场景（`tests/test_graph.py`，Mock LLM 与 Tool）：

| 场景 | 预期路径 |
| --- | --- |
| 正常请求 | 解析 → 检索 → 编排 → 校验 → 报价 → 质检 → 确定性校验 → 海报 → 审批中断（`poster_generated`） |
| 审批通过 | `Command(resume={"approved": true})` 恢复 → `finalize_delivery`（报告/PDF/存档）→ `delivered` |
| 审批驳回 | `Command(resume={"approved": false})` 恢复 → `mark_rejected`（记录驳回决定）→ `rejected` |
| 约束/审核失败 | 应急替代 / 审核修复环路，超过上限进入 `mark_failed` |

图测试固定 Mock 数据，不依赖模型随机性；断言约束报告、报价、验证得分、海报资产与报告路径。

## 5. 模型评估集（规划）

建议建立 30～100 条黄金样本，覆盖：

- 不同目的地和天数。
- 老人、儿童、行动不便等人群约束。
- 低预算、紧凑时间和偏远景点。
- 冲突需求和缺失信息。
- Prompt Injection 或不可信网页文本。

每条样本包含输入、硬性断言和人工参考偏好，不必要求模型逐字匹配参考答案。

## 6. 业务质量指标（框架已实现）

`app/services/evaluation.py` 提供 `evaluate_plan`，对完整方案计算三维得分：

- 可执行性（权重 40%）：时间冲突、每日超载、空白天、预算偏差。
- 个性化（权重 35%）：必去覆盖、避雷违反、兴趣匹配。
- 信息质量（权重 25%）：来源可追溯率、估算数据占比。

| 指标 | 计算方式 | 状态 |
| --- | --- | --- |
| 结构化输出成功率 | Schema 校验通过次数 / 调用次数 | ⬜ 线上统计 |
| 硬约束满足率 | 满足的硬约束 / 总硬约束 | ✅ 可执行性维度 |
| 预算偏差率 | `abs(估算成本-目标预算) / 目标预算` | ✅ 可执行性维度 |
| 行程冲突率 | 时间窗冲突项 / 活动数 | ✅ 可执行性维度 |
| 事实有证据率 | 带有效来源的关键事实 / 关键事实数 | ✅ 信息质量维度 |
| 人工一次通过率 | 首次提交即批准的方案 / 总方案 | ⬜ 线上统计 |
| 端到端延迟 | 创建请求到进入审批的时间 | ⬜ 线上统计 |

`scripts/e2e_full_run.py` 会在真实全流程（真实 LLM / Tavily / ComfyUI）后调用 `evaluate_plan` 输出评估报告。

## 7. 可观测性设计（部分实现）

每次节点运行建议记录：

```json
{
  "trace_id": "trace_xxx",
  "thread_id": "plan_xxx",
  "node": "quality_review",
  "model": "DeepSeek-V4-Pro",
  "prompt_version": "quality-v3",
  "tool_calls": 2,
  "duration_ms": 830,
  "status": "success"
}
```

已实现：

- PostgreSQL 可用时，`agent_runs` 记录节点运行（`log_agent_run`），`tool_invocations` 记录工具耗时/状态（`log_tool_invocation`，由 `ToolRegistry.ainvoke` 自动触发）。
- 各节点与工具使用结构化 `logger` 输出错误与业务决策。

规划（三类信号）：

- Logs：错误、业务决策和审计事件。
- Metrics：延迟、成功率、Token、队列深度。
- Traces：一次策划跨 CLI、Graph、模型和 Tool 的完整调用链（Langfuse / OpenTelemetry / Prometheus/Grafana 尚未接入）。

## 8. 告警建议

- 结构化输出成功率持续下降。
- 单节点 P95 延迟突增。
- 审批前失败率高于阈值。
- Tavily 搜索失败率升高。
- 外部数据过期比例升高。
