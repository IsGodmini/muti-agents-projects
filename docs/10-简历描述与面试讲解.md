# 10｜简历描述与面试讲解

## 1. 一句话介绍

TripOps AI 是一个面向个人用户的对话式多 Agent 旅行策划工具，将需求理解、资源研究、行程优化、成本核算、质量质检和人工审批编排成可恢复的 LangGraph 工作流。

## 2. 项目亮点

- 不是聊天 Demo，而是包含状态机、工具绑定、审批中断和版本设计的业务流程。
- LLM 主导的对话式需求收集，无固定表单，用户自由输入。
- 使用 OR-Tools 处理路线约束，避免让语言模型承担确定性计算。
- 通过 Tavily Remote MCP 做实时网页搜索，所有资源带来源 URL 和检索时间。
- 每个 LangGraph 节点直接绑定所需 Tools，职责清晰、无中间调度层。
- 单一 Ark LLM 完成全部生成节点，结构化输出 + Pydantic 校验。
- 禁止硬编码业务数据，票价、时长、交通时间均由 LLM 估算或搜索获取。

## 3. 简历描述示例

### 精简版

**TripOps AI｜多 Agent 旅行策划助手**

- 基于 LangGraph 设计 12 节点工作流，覆盖需求解析、资源检索、行程编排、路线优化、成本核算、质量审核与人工审批，支持 interrupt 暂停与恢复。
- 接入 Tavily Remote MCP 实现实时景点搜索，结合 LLM 资源充实与 OR-Tools 路线优化，输出带来源证据的可执行行程。
- 使用火山引擎 Ark 完成全部 LLM 节点，统一结构化输出与 Pydantic 校验，关键核算由确定性工具完成。
- 实现对话式 CLI 交互与 JSON 文件持久化，8 个自动化测试全部通过。

### 展开版

**TripOps AI｜多 Agent 旅行策划助手**

- 架构：LangGraph StateGraph 编排 12 个节点，含 2 个条件路由和 1 个人工审批中断；约束失败自动触发应急替代搜索，最多重试 2 次。
- 搜索：作为 MCP Client 接入 Tavily Remote MCP（Streamable HTTP），资源带来源 URL、检索时间和证据，杜绝模型编造景点。
- 优化：LLM 估算资源间交通时间，OR-Tools 求解最优访问顺序并按天分组，避免路线折返。
- 核算：LLM 估算交通/住宿/餐饮/门票成本，确定性工具计算售价与毛利，售价不超过预算上限。
- 质检：LLM 从事实溯源、可行性、客群匹配三维度评分并给出改进建议。
- 工程：Pydantic 全链路校验，Tool Registry 三级风险分级，JSON 文件版本化持久化，ruff + pytest 保证质量。

## 4. 面试讲解要点

### 为什么用 LangGraph 而不是一个 Agent 循环？

旅行策划是有固定阶段的业务流程，不是开放对话。状态图让执行顺序可预测、可测试、可恢复，条件路由把业务决策从 Prompt 中抽离到确定性代码。

### 为什么不用单个大 Prompt？

单 Prompt 的景点是模型记忆（可能过时或编造），路线凭感觉（容易折返），成本是编的数字。本项目用实时搜索保证事实来源，用 OR-Tools 保证路线最优，用确定性工具保证核算准确。

### LLM 和确定性计算如何分工？

LLM 负责理解和生成（需求解析、资源充实、交通估算、行程编排、成本估算、质检）；确定性代码负责硬性约束（validate_constraints）、路线求解（OR-Tools）和最终算术（calculate_product_cost）。事实与创意分离，降低幻觉对报价的影响。

### 为什么移除了 Skill 机制？

最初设计有独立 Skill 调度层，但实践中发现它只是把节点该做的事又包了一层，增加了复杂度却没有带来灵活性。改为每个节点直接绑定 Tools 后，职责更清晰，测试更简单。

### 如何保证搜索结果的可靠性？

资源必须来自 Tavily MCP，带 URL 和检索时间；票价和开放时间由 LLM 估算并标记"需官方确认"；质量审核会检查事实溯源得分，搜索来源的得分上限被压低。

### 审批中断怎么实现？

LangGraph 的 `interrupt` 在 approval_gate 暂停，checkpointer 保存线程状态，CLI 展示方案后用 `Command(resume=...)` 恢复同一 thread_id。当前用 MemorySaver，生产应换持久化 checkpoint。

## 6. 面试边界

面对追问时，最有说服力的方式是区分三个层次：

- 已经实现并测试的部分（工作流、搜索、优化、核算、CLI）。
- 已经设计并提供接口骨架的部分（数据库、文生图）。
- 知道生产环境还需要补充的部分（持久化 checkpoint、认证、可观测性、评估集）。

能清楚解释取舍、失败模式和下一步，比堆叠技术名词更能体现项目深度。
