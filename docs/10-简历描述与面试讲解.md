# 10｜简历描述与面试讲解

## 1. 一句话介绍

TripOps AI 是一个面向个人用户的对话式多 Agent 旅行策划工具，将需求理解、资源研究、行程优化、成本核算、质量质检和人工审批编排成可恢复的 LangGraph 工作流。

## 2. 项目亮点

- 不是聊天 Demo，而是包含状态机、工具绑定、审批中断和版本设计的业务流程。
- LLM 主导的对话式需求收集（独立 chat_graph），无固定表单，用户自由输入。
- 使用 OR-Tools 处理路线约束，避免让语言模型承担确定性计算。
- Tavily Remote MCP + 高德 POI 双路实时检索，所有资源带来源 URL 和检索时间。
- 高德真实交通时间 + LLM 估算兜底，路线优化基于真实数据；和风天气逐日预报参与行程编排。
- 交付物完整：小册子风格 PDF（图文分区、交替排版、总结页）+ Markdown 报告 + 海报素材。
- 每个 LangGraph 节点直接绑定所需 Tools，职责清晰、无中间调度层。
- 多模型分层（复杂/简单/多模态），按任务难度路由，结构化输出 + Pydantic 校验。
- Prompt Injection 防护（Guard）、资源评分排序、确定性校验（verifier）与质量评估框架（evaluation）。
- 禁止硬编码业务数据，票价、时长、交通时间均由 LLM 估算或搜索获取。

## 3. 简历描述示例

### 精简版

**TripOps AI｜多 Agent 旅行策划助手**

- 基于 LangGraph 设计 13 节点工作流，覆盖资源检索、行程编排、路线优化、成本核算、质量审核、确定性校验与人工审批，支持 interrupt 暂停与恢复、约束失败自动重试。
- 接入 Tavily Remote MCP 与高德 POI 双路实时检索，结合 LLM 资源充实与 OR-Tools 路线优化，输出带来源证据的可执行行程。
- 使用火山引擎 Ark 多模型分层完成全部 LLM 节点（复杂推理/对话/多模态），统一结构化输出与 Pydantic 校验，关键核算由确定性工具完成。
- 实现对话式 CLI、FastAPI（含 SSE 流式）、Prompt Injection 防护与 PDF 交付物，19 个单元测试全部通过。

### 展开版

**TripOps AI｜多 Agent 旅行策划助手**

- 架构：LangGraph StateGraph 编排 13 个节点，含 3 个条件路由（约束路由 + 审核路由 + 审批路由）和 1 个人工审批中断；约束失败自动触发应急替代搜索，审核不达标自动进入重排环路，共用重试计数合计最多 2 次。
- 搜索：作为 MCP Client 接入 Tavily Remote MCP（Streamable HTTP），同时接入高德 POI 结构化检索；资源带来源 URL、检索时间和证据，杜绝模型编造景点。
- 优化：高德真实交通时间 + LLM 估算兜底，OR-Tools 求解最优访问顺序并按天分组，避免路线折返。
- 核算：LLM 估算交通/住宿/餐饮/门票成本，确定性工具计算售价与毛利，售价不超过预算上限。
- 质检：LLM 从事实溯源、可行性、客群匹配三维度评分，叠加 8 项确定性校验（verifier）与质量评估框架（evaluation）。
- 防护：检索结果先经过 Prompt Injection Guard 过滤（指令覆盖、角色劫持、工具调用注入等模式）再进入 LLM 上下文。
- 工程：Pydantic 全链路校验，Tool Registry 三级风险分级，JSON 文件版本化持久化，ruff + pytest 保证质量。

## 4. 面试讲解要点

### 为什么用 LangGraph 而不是一个 Agent 循环？

旅行策划是有固定阶段的业务流程，不是开放对话。状态图让执行顺序可预测、可测试、可恢复，条件路由把业务决策从 Prompt 中抽离到确定性代码。

### 为什么不用单个大 Prompt？

单 Prompt 的景点是模型记忆（可能过时或编造），路线凭感觉（容易折返），成本是编的数字。本项目用实时搜索保证事实来源，用 OR-Tools 保证路线最优，用确定性工具保证核算准确。

### LLM 和确定性计算如何分工？

LLM 负责理解和生成（需求收集对话、资源充实、交通估算、行程编排、成本估算、质检）；确定性代码负责硬性约束（validate_constraints + verifier）、路线求解（OR-Tools）和最终算术（calculate_product_cost）。事实与创意分离，降低幻觉对报价的影响。

### 为什么移除了 Skill 机制？

最初设计有独立 Skill 调度层，但实践中发现它只是把节点该做的事又包了一层，增加了复杂度却没有带来灵活性。改为每个节点直接绑定 Tools 后，职责更清晰，测试更简单。

### 如何保证搜索结果的可靠性？

资源必须来自 Tavily MCP / 高德 POI，带 URL 和检索时间；票价和开放时间由 LLM 估算并标记"需官方确认"；质量审核会检查事实溯源得分，搜索来源的得分上限被压低；检索文本先经过注入防护过滤。

### 多模型分层解决了什么问题？

不同任务对推理能力和延迟的要求差异很大：复杂推理（需求分析、成本核算）用 DeepSeek-V4-Pro，对话用 Doubao lite 降低成本，多模态资源充实用 Doubao turbo 结合图片判断景点实况。统一 `ModelGateway` 接口下按 `model` 参数路由。

### 审批中断怎么实现？

`approval_gate` 节点调用 `interrupt()` 暂停，checkpointer 保存线程状态，CLI 或 API 展示方案后用 `Command(resume={"approved": ...})` 恢复同一 `thread_id`；批准进入交付，驳回进入 `mark_rejected` 记录决定。当前用 MemorySaver，生产应换持久化 checkpoint。

## 6. 面试边界

面对追问时，最有说服力的方式是区分三个层次：

- 已经实现并测试的部分（工作流、搜索、优化、核算、CLI、防护、评估）。
- 已经设计并提供接口骨架的部分（文生图、可选 REST API）。
- 知道生产环境还需要补充的部分（持久化 checkpoint、认证、可观测性、评估集）。

能清楚解释取舍、失败模式和下一步，比堆叠技术名词更能体现项目深度。
