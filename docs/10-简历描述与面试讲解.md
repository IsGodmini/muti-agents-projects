# 10｜简历描述与面试讲解

## 1. 一句话介绍

TripOps AI 是一个面向文旅产品经理的多 Agent 策划中台，将需求理解、资源研究、行程优化、成本核算、风险质检、人工审批和营销交付编排成可恢复的 LangGraph 工作流。

## 2. 项目亮点

- 不是聊天 Demo，而是包含状态机、工具权限、审批和版本设计的业务流程。
- 使用 OR-Tools 处理路线约束，避免让语言模型承担确定性计算。
- 将 Tools 与 Skills 分离，支持能力复用、风险分级和独立版本治理。
- 针对本地小模型设计任务路由，用 4B 处理高频轻任务、8B 处理复杂规划。
- 预留 PostGIS、pgvector、Celery 和文生图适配层，形成可演进架构。

## 3. 简历描述示例

### 精简版

**TripOps AI｜多 Agent 文旅产品策划中台**

- 基于 LangGraph 设计需求解析、资源研究、行程规划、路线优化、成本核算、质量审核与人工审批工作流，支持 thread checkpoint 和审批后恢复。
- 实现 Tool Registry 与 Skill Registry，以 Schema、风险等级和工具白名单约束 Agent 能力，并用 OR-Tools 完成多景点路线优化。
- 使用 Next.js + FastAPI 构建前后端，设计 PostgreSQL/PostGIS/pgvector 数据模型及 Ollama、Celery、文生图服务适配层。
- 建立前后端自动化测试，并为生产化补充版本审计、模型路由、RAG 与可观测性方案。

## 4. 三分钟讲解结构

### 第一分钟：业务问题

文旅策划不是单纯写文案。它要同时满足时间、距离、预算、人群和资源时效等约束，而且最终报价和发布需要人工负责。单 Agent 很容易把事实、推理和执行混在一起。

### 第二分钟：核心设计

我用 LangGraph 把流程拆成多个职责节点，共享结构化 State。资源查询、路线优化和成本计算通过 Tool 完成，业务方法沉淀为 Skill。质检后用 interrupt 暂停，审核人员提交结果后通过同一 thread_id 恢复。

### 第三分钟：工程化与权衡

本地有 4B、8B、VL 和文生图模型，我按任务复杂度路由，确定性计算不用模型。演示版采用 MemorySaver 和 Mock 数据保证可测试；生产化会替换为 PostgreSQL checkpoint、真实 RAG、异步队列和全链路观测。

## 5. 演示脚本

1. 首页说明业务价值和流程。

7. 打开架构页说明数据层、模型路由和生产化差距。

## 6. 高频面试问题

### 为什么不用一个 Agent？

复杂任务包含事实查询、约束求解、生成和高风险写操作。拆分后，每个节点可以使用独立 Schema、模型和测试策略，失败时只重试局部。

### Agent、Tool、Skill 有什么区别？

Agent 负责目标和判断，Tool 负责确定性动作，Skill 负责可复用的方法与规则。Agent 只能调用白名单工具。

### 为什么选择 LangGraph？

需要显式状态、条件分支、循环、checkpoint 和人工中断。普通链式调用难以清晰表达审批恢复和局部返工。

### 如何减少幻觉？

事实从检索工具获取，算术和路线由代码完成，模型输出用 Schema 校验，关键事实保留来源，最终商业动作要求人工审批。

### 为什么用 OR-Tools？

路线排序和时间窗是约束优化问题。让语言模型直接算路线难以保证可行性，OR-Tools 的结果可重复、可校验。

### 4B 和 8B 如何分工？

4B 做抽取、分类和格式修复；8B 做跨资源综合规划。通过离线评估决定升级条件，而不是所有节点都使用 8B。

### 如何支持长任务？

用 checkpoint 保存图状态；耗时图片或外部同步任务进入 Celery；API 返回任务标识，前端查询进度。写操作使用幂等键。

### 如何做多租户安全？

生产化需要在 API、checkpoint、数据库和对象存储中都携带 tenant_id，并结合 OIDC/RBAC、工具白名单和行级隔离。

### 当前最大的技术债是什么？

主流程仍以确定性演示数据为主，MemorySaver 无法跨进程恢复。下一阶段优先接入持久化 checkpoint、真实模型节点与资源 RAG，然后建立评估和观测闭环。

## 7. 可以继续实现的迭代

按简历价值排序：

1. 将需求解析和质量审核接入 `qwen3:4b`，加入 Pydantic 重试。
2. 将行程综合规划接入 `qwen3:8b`，实现模型回退策略。
3. 用 PostgreSQL checkpoint 替换 MemorySaver。
4. 实现 PostGIS + pgvector 混合检索和证据引用。
5. 用 Celery 异步生成海报并展示任务进度。
6. 接入 OpenTelemetry/Langfuse，展示节点延迟和质量面板。
7. 增加多租户 RBAC 和高风险工具审批。

## 8. 面试边界

面对追问时，最有说服力的方式是区分三个层次：

- 我已经实现并测试的部分。
- 我已经设计并提供接口骨架的部分。
- 我知道生产环境还需要补充的部分。

能清楚解释取舍、失败模式和下一步，比堆叠技术名词更能体现项目深度。
