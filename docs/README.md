# TripOps AI 文档中心

本目录用于解释 TripOps AI 的业务设计、技术架构、实现边界和演进方案。项目定位是一个“可运行、可演示、可继续扩展”的中型多 Agent 文旅产品策划系统，而不是只展示一次模型调用的聊天 Demo。

## 状态标识

- ✅ 已实现：仓库中已有代码，可在本地运行或测试。
- 🟡 已提供骨架：接口、数据结构或适配层已经存在，但默认运行在 Mock/演示模式。
- ⬜ 演进规划：生产化方案，当前仓库未宣称已经完成。

## 建议阅读路径

第一次了解项目：

1. 阅读项目背景，理解为什么不能用单个大 Prompt 完成。
2. 阅读系统架构和 LangGraph 工作流，理解系统如何拆分职责。
3. 阅读 Tools、Skills 与模型策略，理解模型能力怎样被工程化约束。
4. 按部署文档启动项目，再使用 API 文档做联调。

准备面试：

1. 先读第 10 篇形成 3 分钟项目陈述。
2. 再重点复习第 3、4、5、9 篇。
3. 能够明确回答“已经实现什么、为什么这样设计、下一步怎样生产化”。

## 当前实现快照

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| Next.js 策划工作台 | ✅ | 包含首页、需求录入、方案详情、技能中心和架构页 |
| LangGraph 工作流 | ✅ | 包含多节点编排、状态传递、人工审批中断与恢复 |
| Tool Registry / Skill Registry | ✅ | 支持工具风险元数据与技能清单 |
| OR-Tools 行程优化 | ✅ | 用于候选景点排序与约束求解 |
| FastAPI 服务 | ✅ | 提供健康检查、元数据、运行和审批接口 |
| PostgreSQL + PostGIS + pgvector | 🟡 | 初始化脚本已提供，演示流程仍使用内存数据 |
| Ollama 模型网关 | 🟡 | 适配层已提供，主工作流默认使用确定性演示逻辑 |
| 文生图海报适配器 | 🟡 | 支持 Mock 与真实端点配置，默认展示演示资产 |
| Celery / Redis 异步任务 | 🟡 | 依赖、配置和路由骨架已提供 |
| Tavily Remote MCP 搜索 | ✅ | 使用官方 MCP SDK 调用实时搜索，返回来源和检索时间 |
| 自建 MCP Server、生产级 RAG、全链路观测 | ⬜ | 作为后续演进方向 |

## 文档维护约定

- 新增业务能力时同步修改业务需求、架构和 API 文档。
- 新增 Agent 节点时补充输入、输出、失败策略和可调用工具。
- 新增 Tool 时必须声明风险级别、参数模型和幂等策略。
- 已规划但未落地的能力必须标记为 ⬜，避免把设计方案写成完成项。
