# 01｜项目背景与业务需求

## 1. 项目背景

旅行社、目的地运营商和企业差旅团队经常需要把一段模糊需求转成可售卖的文旅产品。输入可能只有目的地、日期、人数、预算和偏好，交付物却包含行程、交通、住宿、成本、风险提示和宣传素材。

传统流程通常由产品经理在多个网站、表格和聊天工具之间切换，存在三个核心问题：

1. **信息分散**：景点开放时间、距离、价格和适用人群来自不同数据源。
2. **决策耦合**：路线变化会连锁影响用车、酒店、餐饮和报价。
3. **交付不稳定**：不同策划人员的模板、核验标准和文案质量差异明显。

TripOps AI 将该流程建模成多个有明确职责、共享状态和质量关卡的 Agent，由 LangGraph 负责调度。LLM 负责理解与生成，工具负责查询和计算，技能负责固化业务方法和门禁规则，人工负责最终决策。

## 2. 交互方式

系统采用**命令行引导式交互**，通过分步问答收集产品需求：

1. 基础信息：目的地、产品类型、名称
2. 行程周期：天数、晚数
3. 客群与预算：人数、人均预算、毛利率、客群描述
4. 主题选择：多选主题标签
5. 约束条件：硬性限制（分号分隔）
6. 补充信息：自由输入额外需求或特殊情况
7. 需求确认：汇总展示后确认执行

所有字段均有默认值，用户可直接回车跳过。补充信息环节允许输入任意自然语言描述，系统会将其纳入约束条件。

## 3. 典型业务流程

以"为 30 人亲子家庭设计杭州 3 天 2 晚自然研学产品，预算每人 1800 元"为例：

1. **需求解析**（LLM）：提取结构化参数，匹配策划 Skill。
2. **资源检索**（Tavily MCP）：实时搜索目的地景点、活动，保留来源 URL。
3. **资源充实**（LLM）：估算票价、时长、分类和开放时间。
4. **交通估算**（LLM）：估算资源间真实交通时间。
5. **路线优化**（OR-Tools）：基于真实交通时间求解最优访问顺序。
6. **行程编排**（LLM）：生成含午餐、休息、交通间隔的完整时间表。
7. **约束校验**：按 Skill 门禁检查每日时长、交通间隔等。
8. **应急替代**：约束失败时搜索替代资源并重新规划（最多重试 2 次）。
9. **成本核算**（LLM）：基于实际资源票价和目的地市场价估算团队成本。
10. **质量审核**（LLM）：多维度评分，关联 Skill 门禁和约束问题。
11. **人工审批**：CLI 交互式确认，批准或驳回。
12. **交付存档**：方案版本和审批记录持久化到文件。

## 4. 为什么采用多 Agent

单个大 Prompt 可以生成"看起来完整"的行程，但难以稳定保证：

- 行程中的每个资源都能追溯到真实搜索来源。
- 预算变化后，报价和路线同步更新。
- 不同产品类型执行不同的质量门禁（亲子 vs 银龄的强度限制不同）。
- 高风险动作在执行前经过审批。
- 约束失败时能自动搜索替代资源而非简单报错。

多 Agent + 工具 + 技能门禁的组合，让每个环节可验证、可审计、可重试。

## 5. 范围边界

### 系统负责

- 从需求到方案的全流程自动化。
- 资源检索、路线优化、成本计算和质量审核。
- Skill 门禁 enforcement 和应急替代。
- 方案版本管理和审批记录。

### 系统不负责

- 真实预订（酒店、门票、用车）。
- 供应商合同和价格谈判。
- 对客营销文案的最终发布。
- 地图导航和实时交通。
