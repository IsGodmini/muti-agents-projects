# 01｜项目背景与业务需求

## 1. 项目背景

个人用户在规划旅行时，通常需要在多个平台之间反复切换：搜景点、查门票、看地图估距离、排时间、算预算。一趟 3 天旅行的攻略可能需要花 3-5 小时整理，而且结果往往粗糙——时间冲突、路线折返、预算超支。

TripOps AI 是一个面向个人用户的命令行旅行策划助手。用户只需用自然语言说说想去哪、玩几天、几个人、预算多少，系统就会自动完成资源搜索、路线优化、行程编排、成本估算、质量检查和交付物生成，最终输出一份结构完整、可直接执行的旅行方案。

## 2. 目标用户

- **家庭出游**：带孩子旅行的家长，需要控制活动强度、安排休息时间。
- **朋友结伴**：小团体出行，需要兼顾不同兴趣和预算。
- **银龄旅行**：为长辈安排低强度、节奏舒适的慢游行程。
- **个人出行**：想快速拿到一份靠谱攻略的自由行用户。

## 3. 交互方式

命令行对话式交互，由 LLM 主导提问：

1. 用户用一句话描述旅行想法（如"暑假想带孩子去北京玩几天"）。
2. Agent 根据已知信息动态追问关键需求（目的地、天数、人数、预算等）。
3. 信息足够后 Agent 自动开始策划；用户也可随时说"开始吧"立即执行。
4. 工作流输出完整方案，用户在 CLI 中确认存档或放弃。

没有固定表单和预设选项，所有输入都是自由文本，由 LLM 理解并结构化为 `PlanRequest`。对话式需求收集本身也是一个 LangGraph 图（`app/agents/chat_graph.py`），可在 CLI 与 REST API（`/api/v1/chat`）中复用。

## 4. 业务流程

1. **需求收集**（chat_graph / LLM）：对话阶段已完成，输出结构化 `PlanRequest`（含 Agent 假设清单）。
2. **资源检索**（Tavily MCP + 高德 POI 双路）：实时搜索目的地景点/活动网页，同时通过高德获取结构化 POI（坐标、评分、分类）。
3. **防护与充实**：Guard 过滤注入风险内容；LLM 多模态估算票价、时长、分类和开放时间，并可选结合搜索图片判断实况。
4. **评分排序**（确定性）：按兴趣匹配、质量、必去加分、预算/拥挤/天气惩罚计算综合分。
5. **交通估算**（高德真实交通 + LLM 兜底）：有坐标的资源优先用高德路径规划，其余由 LLM 估算。
6. **路线优化**（OR-Tools）：求解最优访问顺序并按天分组。
7. **行程编排**（LLM）：获取目的地逐日天气预报，生成含午餐、休息的完整时间表（雨天安排室内场馆、晴天优先户外）。
8. **约束校验**（确定性规则）：检查空日程、时间冲突、每日跨度、必去覆盖、预算偏差等。
9. **应急替代**：约束不满足时自动搜索替代资源（与审核重排共用重试计数，合计最多 2 次）。
10. **成本估算**（LLM + 计价工具）：估算交通、住宿、餐饮、门票费用并计算售价与毛利。
11. **质量审核**（LLM + 确定性校验）：多维评分 + 8 项确定性可行性检查；任一不达标进入重排环路（共用重试计数）。
12. **海报与交付物**（ComfyUI + Pillow）：生成封面/分日插图海报，合成 Markdown 报告与 PDF。
13. **人工确认**：`approval_gate` 节点调用 `interrupt()` 暂停，CLI/API 提交审批决定后恢复，批准进入交付、驳回记录决定。
14. **方案存档**：版本快照和审批记录持久化为 JSON 文件。

## 5. 为什么不用单个 Prompt

一个大 Prompt 可以生成"看起来完整"的行程，但：

- 景点信息是模型记忆，不是实时搜索，可能过时或编造。
- 路线顺序凭感觉，没有算法优化，容易折返。
- 成本是编的数字，不是基于实际票价的估算。
- 无法在约束失败时自动搜索替代方案。

多 Agent + 实时搜索（Tavily/高德）+ 算法优化（OR-Tools）+ 确定性约束校验的组合，让方案真实、可执行、可验证。
