# 01｜项目背景与业务需求

## 1. 项目背景

个人用户在规划旅行时，通常需要在多个平台之间反复切换：搜景点、查门票、看地图估距离、排时间、算预算。一趟 3 天旅行的攻略可能需要花 3-5 小时整理，而且结果往往粗糙——时间冲突、路线折返、预算超支。

TripOps AI 是一个面向个人用户的命令行旅行策划助手。用户只需回答几个简单问题（去哪、几天、几个人、预算多少），系统就会自动完成资源搜索、路线优化、行程编排、成本估算和质量检查，最终输出一份结构完整、可直接执行的旅行方案。

## 2. 目标用户

- **家庭出游**：带孩子旅行的家长，需要控制活动强度、安排休息时间。
- **朋友结伴**：小团体出行，需要兼顾不同兴趣和预算。
- **企业团建**：行政或 HR 快速生成团建方案初稿。
- **银龄旅行**：为长辈安排低强度、节奏舒适的慢游行程。

## 3. 交互方式

命令行引导式交互，分步收集需求：

1. 目的地、产品类型、名称
2. 天数、晚数
3. 人数、人均预算、客群描述
4. 主题选择（多选）
5. 硬性约束（如"连续乘车不超过 90 分钟"）
6. **自由补充**：任何额外需求或特殊情况
7. 确认执行

所有字段有默认值，可直接回车跳过。

## 4. 业务流程

1. **需求解析**（LLM）：提取结构化参数，匹配策划 Skill。
2. **资源检索**（Tavily MCP）：实时搜索目的地景点和活动。
3. **资源充实**（LLM）：估算票价、时长、分类。
4. **交通估算**（LLM）：估算资源间真实交通时间。
5. **路线优化**（OR-Tools）：求解最优访问顺序。
6. **行程编排**（LLM）：生成含午餐、休息的完整时间表。
7. **约束校验**：按 Skill 门禁检查时长和强度。
8. **应急替代**：约束不满足时自动搜索替代资源。
9. **成本估算**（LLM）：估算交通、住宿、餐饮、门票费用。
10. **质量审核**（LLM）：多维度评分和改进建议。
11. **人工确认**：CLI 交互式审批。
12. **方案存档**：版本和审批记录持久化。

## 5. 为什么不用单个 Prompt

一个大 Prompt 可以生成"看起来完整"的行程，但：

- 景点信息是模型记忆，不是实时搜索，可能过时或编造。
- 路线顺序凭感觉，没有算法优化，容易折返。
- 不同产品类型的约束（亲子 vs 银龄）无法差异化执行。
- 成本是编的数字，不是基于实际票价的估算。
- 无法在约束失败时自动搜索替代方案。

多 Agent + 实时搜索 + 算法优化 + Skill 门禁的组合，让方案真实、可执行、可验证。
